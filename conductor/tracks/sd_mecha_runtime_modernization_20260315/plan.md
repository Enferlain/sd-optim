## Follow-up Ideas

- Replace recipe-mode text rewriting with graph-level editing:
  deserialize the source `.mecha` once, build a stable `ref -> node` map, replace target node args/kwargs directly in the graph, then serialize once at the end.
- Reduce dependence on line-number / `&N` index surgery in `serialize_nodes_for_rewrite()` and `rewrite_recipe_text()`:
  current behavior works, but it is more fragile against future `sd-mecha` serialization changes than direct graph editing would be.
- Split merge artifacts into canonical vs best-effort outputs:
  keep the final `.mecha` recipe plus a small manifest as the authoritative artifacts, and treat the generated runnable Python script as optional debug/repro output.
- Add a merge manifest artifact for recipe mode:
  include source recipe path/hash, target node ref, overridden params, fallback model, model dirs, and output path so reproduction does not depend on Python transpilation.
